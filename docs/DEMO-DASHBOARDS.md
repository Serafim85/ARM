# Дашборды на демо WISLA АРМ — как объяснять

> Дашборды — функция форка **NetworkScanner** (wiSLA NS). В ARM MVP они **не настроены под АРМ**, но пункт меню оставлен намеренно: показываем задел платформы.

---

## Что сказать заказчику (30 сек)

«**Дашборды** — сводные панели оператора: часы, список проблем, графики по выбранным метрикам. Сейчас это модуль общей платформы мониторинга; на пилоте АРМ основной рабочий экран — **реестр АРМ** и **карточка станции**. Дашборд под парк АРМ (Online/Offline, топ инцидентов, заполнение дисков) — логичный следующий шаг в **v1**, виджеты уже есть в продукте.»

---

## Что показывать / не показывать

| | |
|---|---|
| **Показать** | Пункт меню «Дашборды» существует; можно открыть пустой или с 1–2 виджетами |
| **Не обещать** | «Готовый дашборд АРМ из ТЗ» — его ещё нет |
| **Основной фокус демо** | **АРМ** → карточка → **События** → **XLSX** |

---

## Если дашборд пустой («нет виджетов»)

«Шаблон дашборда создан; виджеты добавляются под сценарий оператора. Для демо АРМ мы не наполняли панель — показываем сквозной мониторинг в **АРМ**. В v1 можно собрать виджет „проблемы по тегу arm-workstation“ и график CPU по выбранным хостам.»

---

## Как добавить 1 виджет для красоты (опционально, до демо)

1. **Дашборды** → открыть дашборд → меню **⋮** → добавить виджет  
2. Тип **«Проблемы»** (problems) — покажет OPEN-события мониторинга (после `./infra/demo-trigger-disk-alert.sh`)  
3. Или **«Часы»** — нейтрально, без привязки к SNMP  

Это 2 минуты и дашборд перестаёт быть пустым.

---

## Переход с дашборда на демо АРМ

«Перейдём к предмету пилота — **рабочие станции**.» → клик **АРМ** в меню.
