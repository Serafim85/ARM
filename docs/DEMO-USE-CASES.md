## UC-DEMO-01 — Вход в систему и реестр АРМ

**Цель:** показать единый реестр рабочих станций с актуальным статусом.

**Актор:** инженер техподдержки / оператор мониторинга

**Предусловия:**
- Docker + backend + frontend запущены
- Агенты на `pilot-linux-01` и `pilot-windows-01` в статусе **Online**
- В списке нет лишних `e2e-*` (фильтр `pilot` или очистка БД)

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Открыть http://localhost:3000 | Страница входа |
| 2 | Логин `admin@example.com`, пароль `password`, режим **Локальный** → Вход | Редирект на **АРМ** |
| 3 | Обратить внимание на плитки **Всего / Online / Offline** | Online ≥ 2 |
| 4 | Найти `pilot-linux-01` и `pilot-windows-01` в таблице | Оба **Online**, разные ОС |
| 5 | (Опционально) Фильтр ОС = Linux | Только Linux-хосты |

**Что сказать:**  
«Централизованный реестр АРМ. Статус Online/Offline определяется heartbeat агента — если N минут нет ingest, станция считается недоступной.»

## UC-DEMO-02 — Карточка Linux АРМ и метрики

**Цель:** показать сбор реальных метрик с ОС и историю в БД.

**Предусловия:** UC-DEMO-01 выполнен, `pilot-linux-01` Online

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Клик по строке `pilot-linux-01` | Карточка АРМ |
| 2 | Показать заголовок: hostname, IP, ОС, версия агента | Данные с VM |
| 3 | График **CPU** — период «час» | Кривая меняется |
| 4 | График **Память** и **Диск** | Значения правдоподобны |
| 5 | Переключить период на «сутки» (если есть данные) | История сохранена |

**Что сказать:**  
«Агент Go на Linux собирает CPU, RAM и заполнение системного тома. Данные идут batch-запросом на ingest API, пишутся в TimescaleDB, отображаются по шаблону arm-linux — те же ключи метрик, что в Zabbix-шаблоне.»

## UC-DEMO-04 — Аварийный сценарий: критическое заполнение диска

**Цель:** показать срабатывание порога из шаблона и появление инцидента.

**Предусловия:** стек работает; **до демо** можно один раз прогнать скрипт или оставить live

**Подготовка (до звонка или в перерыве, без показа терминала):**
```bash
./infra/demo-trigger-disk-alert.sh pilot-linux-01
```

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Меню **События** (колокольчик) | Список инцидентов мониторинга |
| 2 | Фильтр / поиск `pilot-linux` | Событие **OPEN** |
| 3 | Открыть строку | Триггер «Root disk space critical», уровень **HIGH** |
| 4 | (Опционально) вкладка Telegram Web | Push-уведомление оператору |

**Что сказать:**  
«Пороги заданы в шаблоне arm-linux. При превышении 95% на диске создаётся инцидент; оператор видит его в UI и может получить уведомление в Telegram или email.»

## UC-DEMO-05 — Закрытие инцидента (resolve)

**Цель:** показать жизненный цикл алерта.

**Подготовка:**
```bash
./infra/demo-trigger-alert-resolve.sh pilot-linux-01
```
*Или дождаться нормальных метрик с VM после снятия `WISLA_ARM_DEMO_DISK_PCT`.*

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | **События** → фильтр RESOLVED / тот же хост | Инцидент закрыт |
| 2 | Показать время breach / normalize | Полный цикл OPEN → RESOLVED |

**Что сказать:**  
«Когда метрика возвращается в норму, триггер автоматически закрывается — это важно для отчётности и SLA.»

## UC-DEMO-07 — Отчёт по парку АРМ (XLSX + рекомендации)

**Цель:** показать задел v1 по отчётности для руководства и ТП.

**Предусловия:** UC-DEMO-04 желателен (чтобы в рекомендациях был HIGH)

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | **АРМ** → кнопка **Экспорт XLSX** | Скачивается `arm-park-report.xlsx` |
| 2 | Открыть файл (Excel / Numbers) | 2 листа |
| 3 | Лист **Реестр АРМ** | hostname, статус, CPU, RAM, диск |
| 4 | Лист **Рекомендации** | Авто-текст: диск, offline, инциденты |
| 5 | (Опционально) меню → **CSV** | Выгрузка реестра |

**Что сказать:**  
«Отчёт по парку для еженедельного обзора: реестр плюс автоматические рекомендации на основе метрик и открытых инцидентов. В v1 — расширенные отчёты и шаблоны под заказчика.»

## UC-DEMO-08 — Интеграция с LDAP (задел v1)

**Цель:** показать готовность к корпоративному входу без live AD на демо.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Выйти → страница логина | Форма входа |
| 2 | Переключатель **LDAP** | Подсказка uid / sAMAccountName |
| 3 | Войти снова локально | Рабочая сессия |
| 4 | **Настройка системы** → блок каталога LDAP/AD | Поля сервера, bind, маппинг групп |

**Что сказать:**  
«Вход через AD/LDAP уже в продукте. На пилоте подключаем каталог заказчика; на демо показываем конфигурацию, live-вход — на стенде заказчика.»

**Не делать на демо:** live LDAP без проверенного тестового сервера.

## UC-DEMO-10 — Потеря связи с агентом (опционально)

**Цель:** offline + алерт connectivity.

**Предусловия:** backend через `./infra/run-backend-demo.sh` (порог offline **2 мин**)

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | На Windows VM остановить агент (Ctrl+C) | — |
| 2 | Подождать ~2–3 мин, обновить **АРМ** | `pilot-windows-01` → **Offline** |
| 3 | **События** | Алерт «workstation offline» |
| 4 | Запустить агент снова | Online + RESOLVED |

**Что сказать:**  
«Если агент перестал слать heartbeat, АРМ уходит в Offline и создаётся операторское событие.»

**На удалённом демо:** лучше **заранее** сделать скриншот Offline или пропустить — долго ждать в эфире.
